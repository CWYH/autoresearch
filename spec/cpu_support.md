# CPU Smoke-Test Version Plan

## Summary

Generate an independent CPU version under `cpu/` without modifying the existing `prepare.py`, `train.py`, or `program.md`. The CPU version is intended to validate the end-to-end path on real data: data preparation, tokenizer loading, CPU dataloader, small GPT training, and metric output. It should default to a short smoke test, while still supporting `--seconds 300` for a 5-minute CPU training attempt.

## Key Changes

- Add `cpu/train_cpu.py`.
- Use CPU only: `device = torch.device("cpu")`; do not call `torch.cuda.*`, Flash Attention, CUDA autocast, or the original CUDA-backed `prepare.make_dataloader()`.
- Import only CPU-safe pieces from `prepare.py`, such as `Tokenizer`, `DATA_DIR`, `TOKENIZER_DIR`, and `VAL_FILENAME`.
- Implement a CPU dataloader that reads real parquet shards, tokenizes text, and yields `(x, y)` next-token batches.
- Implement a small decoder-only language model suitable for CPU smoke tests, using token embeddings, positional embeddings, causal self-attention, MLP blocks, and an LM head.
- Default to small parameters such as `--seq-len 128`, `--batch-size 2`, `--n-layer 2`, `--n-embd 128`, `--n-head 4`, and `--seconds 60`.
- Print a final summary including `val_loss`, `train_seconds`, `total_seconds`, `num_steps`, `num_params_M`, and `device=cpu`.

Add `cpu/README.md` documenting that this is a CPU smoke-test version, not a benchmark-equivalent replacement for the CUDA path. Include these commands:

```bash
uv run prepare.py --num-shards 1
uv run cpu/train_cpu.py
uv run cpu/train_cpu.py --seconds 300
```

## Execution Plan

1. Confirm the working tree state before editing.
2. Create `cpu/train_cpu.py` and `cpu/README.md` only.
3. Prepare real data with one training shard plus the pinned validation shard:

```bash
uv run prepare.py --num-shards 1
```

4. Run a short CPU smoke test:

```bash
uv run cpu/train_cpu.py
```

5. If the smoke test succeeds, attempt a 5-minute CPU run:

```bash
uv run cpu/train_cpu.py --seconds 300
```

6. Record the observed result: whether data preparation completed, number of training steps, final loss, elapsed time, and any failure reason.

## Test Plan

- Static safety check: confirm `git diff -- prepare.py train.py program.md` is empty.
- Data check: confirm `~/.cache/autoresearch/data` contains at least one training shard and the pinned validation shard.
- CPU path check: run `uv run cpu/train_cpu.py --seconds 10` and confirm no CUDA calls are required.
- Default smoke test: run `uv run cpu/train_cpu.py` and confirm it prints loss and step count.
- Long-run attempt: run `uv run cpu/train_cpu.py --seconds 300` and confirm it either completes or reports a clear failure.

## Assumptions

- The CPU implementation lives in a new `cpu/` subdirectory.
- Real shard data is used; no synthetic local dataset is generated by default.
- The default run is a short smoke test, while 5-minute CPU training is opt-in via `--seconds 300`.
- Existing `prepare.py`, `train.py`, and `program.md` remain unchanged.
- CPU results validate functionality only and are not comparable to the original CUDA `val_bpb` benchmark.
